# Проход по лицу на проходной кампуса

Кадр с камеры проходит на edge-узле детекцию, гейт качества, проверку живости, извлечение дескриптора и поиск по галерее площадки; правила выдают один из трёх исходов (`allow`, `manual_review`, `deny`), команду контроллеру турникета и запись в журнал доступа с машиночитаемой причиной. Ни одна деградация не открывает проход автоматически: плохой кадр, подозрение на предъявление экрана, близкий второй кандидат и устаревший кеш уходят охране. Целевая архитектура в [docs/](docs/), работающий код в [poc/](poc/).

## Запуск

Нужен Python 3.10 или новее.

```bash
pip install -r requirements.txt
make demo   # пять событий с проходной плюс повтор первого
make test   # 10 тестов, 1.3 с
```

Без make: `cd poc && python3 run_demo.py` и `cd poc && python3 -m pytest -q`. Решения пишутся в `poc/out/access_log.jsonl`, по строке JSON на запись.

## Демонстрируемый сценарий

```
галерея на edge: 6 сотрудников, вектор 84-D

event   решение        сотрудник    score  margin  liveness  кадров          команда  причины
---------------------------------------------------------------------------------------------
e-1001  allow          emp-4821     1.000   0.099       8.1       1             open  quality_ok, liveness_ok, match_above_allow_threshold
e-1002  manual_review  -            0.000   0.000       5.7       3      keep_closed  face_occluded
e-1003  deny           -            0.000   0.000      20.3       1      keep_closed  liveness_failed
e-1004  manual_review  emp-2290     0.816   0.005       8.5       1      keep_closed  quality_ok, liveness_ok, second_candidate_too_close
e-1005  manual_review  emp-3140     1.000   0.248       3.4       1      keep_closed  quality_ok, liveness_ok, degraded_stale_cache, revocation_may_be_stale
e-1001  allow          emp-4821     1.000   0.099       8.1       1             none  quality_ok, liveness_ok, match_above_allow_threshold, idempotent_replay

турникет открывался 1 раз(а)
журнал доступа: out/access_log.jsonl (6 записей)
```

Happy path один, рискованных путей четыре, и ни один не открывает турникет: маска и контровый свет съедают три кадра retry и уходят охране; кадр с экрана телефона даёт `deny` по живости (20.3 против порога отказа 14.0); два близких кандидата уходят человеку при уверенном score 0.816 и margin 0.005; offline с кешем возрастом 240 минут закрыт независимо от score, потому что отзыв доступа физически не мог доехать до узла. Повтор `e-1001` возвращает сохранённое решение без второго импульса контроллеру и попадает в журнал отдельной записью: попытка переиграть событие должна быть видна при разборе.

## Что реально, а что дизайн

| Стадия горячего пути | В прототипе | В целевой системе |
|---|---|---|
| Детекция лица | реально: каскад Хаара, OpenCV | YuNet (MIT) или SCRFD на GPU-узлах |
| Качество кадра | реально: резкость, яркость, доля кадра под лицом, пересвет нижней половины лица | признаки ISO/IEC 29794-5, реализация OFIQ |
| Живость (PAD) | реально: периодичность строк в спектре, порог отказа 14.0 | обученный PAD класса DeepPixBiS, затем NIR-канал |
| Дескриптор лица | mock: спектральный вектор 84-D, распознавание не решает | ArcFace R50, 512-D, косинус на L2-нормированных |
| Поиск по галерее | реально: полный перебор с отрывом от второго кандидата | тот же интерфейс `search(vector, k)`, HNSW на 500 000 векторов в центре |
| Правила решения | реально: три порога (0.80 / 0.55 / margin 0.06), retry, режимы кеша, revocation list, идемпотентность | без изменений: пороги правит ИБ через конфиг, без релиза кода |
| Турникет | mock: печать команды с дедупом по `decision_id` | REST поверх mTLS, для legacy-панелей OSDP Secure Channel |
| Центральный сервис | mock: локальный объект `EdgeCache` | энролмент, мастер-база шаблонов, ANN-индекс, аудит, интерфейс охраны |

Код прототипа: [vision.py](poc/facegate/vision.py), [embed.py](poc/facegate/embed.py), [gallery.py](poc/facegate/gallery.py), [policy.py](poc/facegate/policy.py), [config.py](poc/facegate/config.py). Библиотеки: numpy, opencv-python-headless, pillow, pytest.

Два mock объясняю отдельно, потому что от них зависит доверие к цифрам в выводе. Дескриптор вместо ArcFace: собирать биометрию задание запрещает, а веса insightface лицензированы research only, поэтому score говорят о поведении метрики на синтетике, а не о точности распознавания. Кадры рисуются процедурно и на диск не пишутся ([frames.py](poc/facegate/frames.py)): фронтальная геометрия с овалом, глазами, носом и ртом нужна, чтобы лицо находил каскад Хаара, а идентичность задана низкочастотным паттерном на области лица, потому что его различает спектральный дескриптор и он предсказуемо слабеет при размытии.

Вне таблицы остался дизайн, который прототип не трогает совсем: шифрование галереи AES-256-GCM с ключом в TPM, репликация галереи и подписанный revocation list, интерфейс ручной проверки для охраны ([architecture.md](docs/architecture.md), [ml.md](docs/ml.md)).

## Допущения и незакрытые риски

Пороги подобраны по шести синтетическим кадрам и о реальной точности не говорят: калибровать их можно только на боевых камерах в shadow-режиме. Галерея на edge сужена до 4 000 активных сотрудников площадки, иначе FPIR при поиске 1:N выходит за допустимое. Цена одного false accept принята 1 млн ₽ против 4 ₽ у ложного отказа при живой карте, и это отношение назначено политикой безопасности, а не измерено.

Не закрыто в MVP: кросс-доменная деградация PAD (лабораторные ACER около 1 % дают HTER 10-20 % на чужой камере), цена лицензии FR-SDK 0.3-1.0 млн ₽ в год перекрывает весь твёрдый эффект, правовая экспертиза по 572-ФЗ и ЕБС не проведена, истинный false accept rate в эксплуатации не наблюдаем. Полные списки допущений, компромиссов и рисков в [SELF_REVIEW.md](SELF_REVIEW.md).

## Ценность для бизнеса

Твёрдый эффект MVP 0.69 млн ₽ в год: разборы у охраны падают с 40 до 18 в день, перевыпуск карт вдвое ([product.md](docs/product.md)). Мягкий эффект 21.9 млн ₽ в год держим отдельной строкой как upside, потому что экономия 93 секунд на пиковом проходе дойдёт до P&L только если высвобожденное время превратится в работу. Карта остаётся обязательной небиометрической альтернативой и одновременно fallback при ложном отказе: она стоит проекту ноль рублей и поднимает допустимый FRR с 0.15 до 5 процентов, то есть в тридцать с лишним раз. Главный эффект деньгами не считается: карту можно передать коллеге, а лицо привязывает проход к человеку, и расследование идёт запросом по `event_id`, а не просмотром видеоархива.
